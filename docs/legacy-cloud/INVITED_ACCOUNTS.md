# 招待制アカウントへの変更記録

この文書は新しいマスター仕様ではありません。マスター仕様は `PROMPT_TREE_MASTER_SPEC.md` のまま保持し、その後の明示的なユーザー指示を実装した記録です。

## ユーザーが指定した変更

- 公開URLを知っていればログイン画面は誰でも開ける。
- 個人データの利用には認証が必要。
- 登録できるのは招待された人のみ。

## 実装した動作

最初のOwnerはユーザー名 `owner` の招待管理者です。Settingsから招待リンクを発行・取り消しできます。リンクは256bitのランダム値を使い、DBにはハッシュのみを保存します。7日間有効・1回限りです。URL fragmentに置くため通常のHTTPリクエストやRefererにはトークンを含めません。登録と招待消費は1トランザクションで行い、同時登録でも1人だけが成功します。

招待された人は自分のユーザー名・12文字以上のパスワード・4桁PINで登録します。ログイン後にPINを解除し、5分無操作でAPIもロックします。ユーザー名は大文字・小文字を区別しません。ログイン・登録の送信元レート制限と、アカウントごとの失敗回数・バックオフを適用します。

各ユーザーのSeries・Card・複数画像・接続・タグ・検索・設定・容量表示・書き出しを分離します。管理者のアプリ権限は招待管理であり、他アカウントの画像やデータを閲覧するAPI権限はありません。Cloudflare管理権限を持つインフラ管理者は別途DB・R2を管理できます。

R2バケットは非公開のままです。Originalはバイト列を変更せず保存します。所有者検証を経由して取得します。アカウント変更時に端末の旧キャッシュ・下書き・Undoを消去し、キャッシュキーとオフラインPIN検証をユーザーに結び付けます。旧アカウントの遅れて返るAPI応答は破棄します。別タブのアカウント切り替えも表示を閉じます。

## 移行

`0007_invited_accounts.sql` は既存 `owner` のID・パスワード/PINハッシュ・参照先を保持し、招待管理者として移行します。既存OriginalのR2キーを書き換えたり画像を再圧縮したりしません。既存DBの削除・再作成やデータの初期化は不要です。

本番移行前には対象D1/R2をバックアップし、migrationを適用して `PRAGMA foreign_key_check` を確認します。ローカルDBのバックアップはサーバー停止中に `.wrangler/state` 全体を保全します。既存データを含むSQLiteで全参照と資格情報を比較するテスト、および既存ローカルD1への適用を行います。

## 公開に必要な外部設定

Cloudflare Workers・D1・非公開R2、および初期Owner設定用のランダムなSETUP_TOKENが必要です。現在のローカルURL `127.0.0.1:8787` はこのPC専用で、インターネット公開URLではありません。Cloudflareの認証と本番リソース設定・デプロイが完了してから、共有できるHTTPS URLが発行されます。検証用DB・テスト用パスワードは本番へ移しません。
